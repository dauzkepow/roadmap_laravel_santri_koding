3. JWT (RFC 7519)= mengamankan client server dengan JSON, otentikasi dan otorisasi
- struktur jwt dipisahkan oleh titik ( . )
    1. header = jenis token, dan algoritma tanda tangan HMAC SHA256 atau RSA
    {
        "alg": "HS256",
        "typ": "JWT"
    }

    2. payload = pernyataan entitas user
    {
        "sub": "1234567890",
        "name": "John Doe",
        "admin": true
    }

    3. signature = ambil encoded header, encoded payload, secret, dan algoritma header
    HMACSHA256(
        base64UrlEncode(header) + "." + base64UrlEncode(payload),
        secret)
    JWT biasanya seperti ini :
    eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiYWRtaW4iOnRydWV9.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

- Penggunaan JWT
    1. otentikasi 
    setelah login server membuat jwt lalu mengirimkan ke user
    user simpan token di localstorage atau cookies dan kirim setiap request ke server
    server mem-verifikasi token setiap permintaan untuk memastikan user yang sah

    2. otorisasi
    jwt dapat digunakan untuk memastikan pengguna memiliki izin akses ke layanan tertentu
    dengan memeriksa klaim payload jwt server dapat menentukan hak akses user

- Kelebihan
    1. Portabilitas = mudah digunakan, dibaca dalam berbagai bahasa pemrograman
    2. kemandirian = semua informasi yang diperlukan untuk verifikasi user disimpan
    dalam token itu sendiri, sehingga mengurangi kebutuhan berganting pada penyimpanan
    sesi di server
    3. keamanan = jwt ditandatangani menggunakan algoritma kriptografi yang memastikan
    bahwa payload tidak dapat diubah tanpa mendeteksi perubahan tersebut
    4. skalabilitas = karena jwt self-contained, server dapat menangani lebih banyak
    permintaan tanpa perlu memeriksa database atau penyimpanan sesi pada setiap 
    permintaan
